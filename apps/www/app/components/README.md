# `app/components` — folder convention

Two folders, one rule: **`ui/` is generated, everything under `custom/` is ours.**

```
app/components/
├─ ui/        # GENERATED by shadcn — vendored primitives. DO NOT edit or add
│             #   files by hand. `shadcn add` writes/overwrites here.
│             #   (Button, Card, Dialog, …) — see ui/README.md.
└─ custom/    # OURS — reusable components. Composed from ui/ + Tailwind.
   ├─ layout/     # layout primitives: stack.tsx, container.tsx (+ tokens.ts,
   │              #   the shared spacing scale). Use instead of hand-writing
   │              #   flex/gap/max-width. Grown as needed (YAGNI).
   ├─ typography/ # text.tsx — one <Text variant> (hero/title/subtitle/
   │              #   overline/body1/body2) instead of raw text-*.
   ├─ app-layout.tsx    # shared page frame
   └─ brand-header.tsx  # brand identity block
```

## Styling convention: wrap Tailwind, don't scatter it

Treat raw Tailwind as low-level "framework" code and **compose pages from named
components**, not utility soup:

- **Layout/structure** (flex, gap, max-width, layout padding) → use the
  `custom/layout/` primitives (`Stack`, `Container`), never hand-written
  `flex/gap/…` in pages. Add primitives/scale steps only when a screen needs
  them (YAGNI) — don't pre-build variants.
- **Recurring or named visual patterns** → extract a component.
- **Tokens** (color, spacing, radius, font) → centralized in `app/app.css` +
  `layout/tokens.ts`. No stray hex/px.
- **Escape hatch:** primitives accept `className` for genuine one-offs — keep
  those rare. Wrap what *repeats or has a name*; don't make a component for
  every `<div>`.

## How this fits the rest of `app/`

```
app/
├─ root.tsx      # document + app-wide background; wraps every page in <AppLayout>
├─ components/   # ui/ (generated) + custom/ (reusable, this folder)
├─ pages/        # PAGE components — one per screen (login-page, home-page, …).
│                #   DATA GATHERERS: they call hooks (useSession, useMe, …) and
│                #   take NO data props. Composed from components/. Run by routes.
├─ routes/       # React Router route modules — thin auth/routing glue that
│                #   gates + picks which page to render (home.tsx → Login vs Home).
└─ lib/          # non-visual helpers (auth client, cn util).
```

Rule of thumb: **routes** gate + decide *what* to show, **pages** are *a whole
screen that fetches its own data*, **components/custom** are *reused across
pages*, **components/ui** are *generated*.

## The rule

- **`components/ui/`** — shadcn output only. If a file is here, it's generated
  and treated as a black box you _use_, not edit (it can be overwritten by
  `pnpm dlx shadcn@latest add <name>`). Details in [`ui/README.md`](./ui/README.md).
- **`components/custom/`** — everything we author. Flat (no sub-folders) for
  now; revisit if it gets crowded. Name files in kebab-case, export PascalCase
  (e.g. `page-shell.tsx` → `PageShell`).

## Why the split

shadcn's model copies component source into the repo, so generated and
hand-written code would otherwise sit side by side and blur together. Keeping
generated code quarantined in `ui/` makes it obvious what's safe to edit, what
gets regenerated, and where our own work lives.

## Import aliases

- Generated: `~/components/ui/<name>` (e.g. `~/components/ui/button`)
- Ours: `~/components/custom/<name>` (e.g. `~/components/custom/page-shell`)
