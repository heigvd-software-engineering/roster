# `app/components` folder convention

Two folders, one rule: **`ui/` is generated, everything under `custom/` is ours.**

```
app/components/
├─ ui/        # GENERATED by shadcn. DO NOT edit or add files by hand;
│             #   `shadcn add` writes/overwrites here. See "The ui/ folder".
└─ custom/    # OURS, reusable components grouped by concern:
   ├─ layout/     # stack.tsx, row.tsx, container.tsx, page.tsx (+ tokens.ts,
   │              #   the shared spacing scale). Use instead of hand-writing
   │              #   flex/gap/max-width. Grown as needed (YAGNI).
   ├─ typography/ # text.tsx: <Text variant>, the one typography component.
   ├─ shell/      # app chrome + gating: app-layout, app-header, auth (route
   │              #   guard), main-switch-identity (the account menu).
   ├─ identity/   # user-avatar (the primitive), user-identity (THE person row),
   │              #   org-identity, emails-menu. lib/identity.ts decides who a
   │              #   person is named by, and so whether they wear a photo or
   │              #   initials.
   ├─ rules/      # axiom.tsx, rule-item.tsx, rule-phase.tsx: the pieces the
   │              #   "How roster works" page (pages/rules-page.tsx) composes.
   ├─ classes/    # classes-domain components, see "Import aliases" below.
   └─ *.tsx       # cross-cutting one-offs several folders compose: command-block,
                  #   confirm-dialog, disabled-reason, disclosure-toggle, hint,
                  #   loading, state-change. A file earns the root by being
                  #   domain-less, not by being small; classes-specific files
                  #   go in classes/.
```

Name files in kebab-case, export PascalCase (`class-card.tsx` → `ClassCard`).

## Styling convention: wrap Tailwind, don't scatter it

Treat raw Tailwind as low-level "framework" code and **compose pages from named
components**:

- **Layout/structure** (flex, gap, max-width, layout padding) → use the
  `custom/layout/` primitives (`Stack`, `Container`), never hand-written
  `flex/gap/…` in pages. Add primitives and scale steps only when a screen needs
  them (YAGNI).
- **Recurring or named visual patterns** → extract a component.
- **Tokens** (color, spacing, radius, font) → centralized in `app/app.css` +
  `layout/tokens.ts`. No stray hex/px.
- **Escape hatch:** primitives accept `className` for genuine one-offs. Keep
  those rare. Wrap what *repeats or has a name*.

## How this fits the rest of `app/`

```
app/
├─ root.tsx      # document + app-wide background; wraps every page in <AppLayout>,
│                #   inside ThemeProvider > MessageProvider > AuthProvider
├─ routes.ts     # the route table
├─ components/   # ui/ (generated) + custom/ (reusable, this folder)
├─ contexts/     # the providers those hooks read: auth-context (useAuth),
│                #   message-context (useMessage), theme-context
├─ pages/        # PAGE components, one per screen (login-page, classes-page, …).
│                #   DATA GATHERERS: they call hooks (useAuth, useApi, …) and
│                #   take NO data props. Composed from components/, run by routes.
├─ routes/       # React Router route modules: thin auth/routing glue that
│                #   gates + picks which page to render (home.tsx → Login when
│                #   signed out, else redirect to /classes).
├─ lib/          # non-visual helpers: api.ts (the hc<AppType> client + useApi),
│                #   auth.ts, identity.ts, format.ts, semester.ts, theme.ts,
│                #   utils.ts (cn).
└─ app.css       # design tokens (:root / .dark / .terminal)
```

## Import aliases

`~/*` resolves to `./app/*`, so:

- Generated: `~/components/ui/<name>` (e.g. `~/components/ui/button`)
- Ours: `~/components/custom/<group>/<name>` (e.g. `~/components/custom/classes/hub/class-card`)

Large groups split further by use case: `classes/` holds `hub/` (the classes
page cards + dialogs), `assignments/` (`assignments-table`, `assignment-header`, `assignment-status`,
`deadline-text`, and the create/edit `assignment-dialog`), `reconcile/` (the
drift-audit explainer dialog), and
`groups/` (everything both assignment pages compose), itself split by role:

- `groups/shared/`: used by both roles, the `use-assignment-groups` hook plus the
  shared `group-card` / `unassigned-pool` / `new-group-dialog` / `seats` /
  `work-repo`.
- `groups/teacher/`: the teacher's assignment roster: `teacher-assignment-groups`
  + its `group-status` / `assignment-stats` / `clone-all-dialog` bits.
- `groups/student/`: the student's view: `student-assignment-groups` +
  `start-assignment-card`.

Cross-cutting pieces (`role-marker`) stay at the `classes/` root.

## The `ui/` folder: shadcn components, vendored

**Do not hand-write files there, and treat them as a black box you _use_, not
edit.** Everything in it is generated by the [shadcn](https://ui.shadcn.com)
CLI, which copies canonical component source into the repo; quarantining it
keeps it obvious what gets regenerated and what is ours. Present today:
`avatar`, `badge`, `button`, `card`, `dialog`, `dropdown-menu`, `input`,
`label`, `popover`, `select`, `switch`, `table`, `toggle`, `toggle-group`,
`tooltip`.

They are built from up to three layers:

- **Base UI** (`@base-ui/react`): unstyled, accessible primitives (focus,
  keyboard nav, ARIA). This is our chosen primitive layer (shadcn's
  `--base base`). Most components wrap it; the plain styled ones (`card`,
  `label`, `table`) have no behaviour to borrow and don't.
- **Tailwind**: all styling, as utility-class strings. Hence the density (long
  class strings + `data-[…]`/`aria-[…]` selectors in `button.tsx`).
- **CVA** (`class-variance-authority`) + `cn()` (`~/lib/utils`): manage
  `variant`/`size` options and merge classes. Only the components with variants
  use it: `badge`, `button`, `toggle`, `toggle-group`.

You consume them: `<Button variant="outline" size="lg">Save</Button>`.

### Adding one

```bash
pnpm dlx shadcn@latest add <name> --cwd apps/www   # e.g. card, dialog, input
```

It lands in `ui/`. Run the formatter over it, then the gate:

```bash
pnpm exec biome check --write apps/www/app/components/ui/<name>.tsx
pnpm run biome && pnpm -r typecheck && pnpm -r test
```

To pull upstream fixes, re-run `shadcn add <name>`; it overwrites the file,
which is why hand-edits are discouraged. Prefer composing these primitives over
editing them; if you must customise, keep parity with shadcn conventions. Icons
come from [`lucide-react`](https://lucide.dev).

### Config, outside the folder

- `apps/www/components.json`: shadcn config (style `base-nova`, base color
  `neutral`, `lucide` icons, `~/` aliases). Source of truth for the CLI. The
  folder was initialised once with
  `pnpm dlx shadcn@latest init --cwd apps/www --template react-router --base base --preset nova --yes`,
  which also wrote `~/lib/utils.ts` (`cn`) and injected the tokens into
  `app/app.css`.
- `apps/www/app/app.css`: design tokens (`:root`/`.dark` CSS variables) that
  every component reads. Edit colours/radius/fonts there, app-wide. These are
  shadcn's stock `neutral` tokens, unmodified apart from the two font
  families: state is expressed with the stock tokens (`foreground`,
  `muted-foreground`, `destructive`) and shadcn's own `Badge`/`Button`
  variants, so no app-specific hue has to be kept in sync with a component.
